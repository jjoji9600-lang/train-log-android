# 加班留证 · Overtime Evidence (Android MVP)

用于日常保存加班相关材料并按**单次加班事件**整理、导出。**本应用只是证据整理辅助工具，不会自动认定加班、计算应付加班费，也不能保证仲裁采纳。**

## v0.3.2 操作指引（不改变证据存储方式）

本版主要调整 **操作顺序、上下文提示与用词一致性**，不是更换视觉主题。上传与编辑材料都只要求选择三要素并填写说明，不再出现第二套重复的证据分类。编辑弹窗可以滚动，适配短屏手机。

- 首页不再把月度累计时间放在最显眼的位置。优先显示当前/最近一次记录的 **建议下一步、为什么这么做、三要素标注进度**。
- 每次加班详情顶部只给一个随数据变化的主要动作：先核对待整理事件 → 首次保存材料 → 补齐未标注类别 → 结束计时 → 导出备份。实际计时结束可以随时按「结束计时」，**不强制先收集齐三要素**。
- 三要素清单统一显示「已标注 / 待补充」；逐项解释 **为什么要收集、建议保存什么**。这是归档引导，不是法院认可的固定证据数量要求。
- 文件选择或拍照之后，用日常语言引导「选出能说明的事项 → 写下截图的具体内容 → 保存材料」。同一批多份材料共用说明时明确提醒分批导入。
- 结束计时前确认：说明停止计时不影响以后补证；缺项仍会留在详情页提醒。
- 「整理以前的截图」会创建一条待整理记录，并特别提示导入时间 **不等于实际加班时间**；需要自行补充工作时间、材料来源和任务说明。
- 有实质变动的步骤增加了 JVM 导引规则测试，Android 设备 UI 测试跟随同一套文字与操作逻辑。

## 已实现

- 一键开始、结束加班记录（使用手机系统时间；未自动扣除休息时间）。
- 从相册/文件管理器导入图片、PDF、文本或其他文件；在微信、钉钉等 App 里使用 Android **分享**功能发送截图到「加班留证」。
- 调用系统相机拍照并归档。无活跃加班事件时，导入会创建「待整理」记录。拍照和文件选择进行中若 Activity 被重建，会尝试恢复当前事件、照片文件名和导出请求。
- **新增三要素留证流程**：拍照、文件选择或系统分享后，先勾选「加班事实」「公司安排」「时长与工资」（可多选），并填写内容说明，确认后才保存到证据库。
- 原有的详细分类仍保留在兼容性的导出元数据中，但界面仅展示三要素，详细分类由程序根据三要素自动维护。
- 附件导入时保留输入流的原始字节，计算 SHA-256，使用 Android Keystore 提供的 AES-256-GCM 密钥加密后存入应用私有目录。
- 按每次加班事件统计三要素已标注的材料数，对尚无材料的要素**持续展示提醒、补充建议及快捷导入入口**；结束加班时也通过 App 内提示提醒缺项。不申请系统通知权限，也不在后台推送。
- 老版本材料未标注三要素时，按「待补标」处理，避免将旧分类误当成已提交三要素材料。
- 按事件导出 ZIP：`report.pdf`（目录）、`manifest.json`（结构化清单）、`originals/`（解密后的原始文件字节）、`SHA256SUMS.txt`（哈希校验）、`README.txt`。
- 默认无网络权限；无需注册和账号。使用 Android 文档选择器和分享权限，不申请访问整个手机存储的权限。

## 隐私 / 证据边界

- **附件内容加密**；事件标题、备注、附件文件名、时间和哈希存储在应用私有目录的 `manifest.json` 中，**MVP 暂未对这些元数据加密**。设备被入侵或 root 后无法保证这些数据不被访问。
- 加密密钥位于 Android Keystore，**不能通过拷贝 App 数据目录跨设备恢复**。不要只依赖本地存储；定期导出到可靠位置。卸载 App 可能造成不可恢复的数据丢失。
- 导出 ZIP **不加密**，包含原始文件。保存、传输或提交前检查无关的个人信息、客户隐私和商业秘密；只收集依法可留存的材料。
- 设备时钟、原始文件的元数据以及截图内容**不构成第三方可信时间戳**；SHA-256 只能校验保存之后有无改变，不能证明截图拍摄之初真实。
- 三要素勾选、分类和说明是**用户的陈述**，不能保证材料的相关性、真实性或证明力。即使三项都勾选，也不意味着加班费请求成立。
- 用户取消拍照归档时，不会写入证据库；导入失败时保留确认界面以便重试。
- 导入的截图可能不包含全部上下文，尽量保留完整原始聊天、任务、考勤系统记录和其他客观材料。

## 如何构建

需要 JDK 17、Android SDK Platform 36、Gradle 8.13 和联网下载 Gradle/AndroidX 依赖，或者通过 Android Studio 打开根目录并配置本地 Gradle 8.13。此快照未包含 Gradle Wrapper JAR。

```bash
gradle :app:testDebugUnitTest :app:assembleDebug --no-daemon
```

调试包位置：`app/build/outputs/apk/debug/app-debug.apk`。

GitHub Actions 的源码构建任务会执行 JVM 单元测试、编译 Android instrumentation tests 并构建调试 APK。仓库根目录的 `.github/workflows/overtime-evidence-emulator.yml` 会尝试在 Android 35 模拟器上实际运行这些设备测试。

**设备测试覆盖**：生成样例图片，通过 Android FileProvider / ContentResolver 导入；验证本地 AES-GCM 解密与 SHA-256、三要素缺项变化、结束加班后补证、重新创建 Repository、导出 ZIP/PDF/manifest 与原件一致性。另有 Compose UI 测试覆盖新建事件、模拟 Android 分享、勾选要素、填写说明、确认归档和结束加班提醒。

**仍未覆盖**：手机厂商的真实拍照 App、后台回收的全部机型场景、微信/钉钉权限变化、用户真实业务证据质量。通过模拟器测试不等于真机全面验证。

## 使用步骤

1. 点击「＋ 开始加班」填写任务，进入记录详情后按页面的下一步建议拍照或导入材料。
2. 在导入弹窗中勾选该材料能帮助证明的三要素（可多选），填写具体内容，然后「确认归档」。
3. 返回加班详情查看顶部的「建议你现在做什么」和逐项缺口说明，按推荐操作即可。
4. 结束加班后继续补充材料和说明；点击「导出 ZIP」，在 PDF 和 JSON 里核对标签、描述与缺项清单。

## 技术

Kotlin + Jetpack Compose；应用私有文件存储 + 原子写入 JSON 元数据；AES-GCM（Android Keystore）；Android `PdfDocument`、`ZipOutputStream`。设计为离线单机 MVP，不含云端、账号、广告、埋点。
